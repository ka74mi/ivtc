## ivtc-cli-dump

`ivtc-cli dump` は、NV12 の raw フレームをフレームごとに解析し、縞量と差分の特徴量を CSV で出力する。IVTC の判定は行わない。設計の確定前に、実動画で位相ジャンプ・ダブり (D)・通常のサイクルを区別できる指標を探すための解析用 (`docs/ivtc-design-options.md` の「実動画で確かめたいこと」)。

凡例: [確定] はコードとテストで確認済み、[仮説] は未検証の推測、[未確認] は未調査。

### 使い方

```
ffmpeg -ss <開始> -t <長さ> -i in.ts -an -fps_mode passthrough -pix_fmt nv12 -f rawvideo - \
  | ivtc-cli dump --width 1440 --height 1080 --field-order tff > out.csv
```

- `--width`、`--height`: 入力の画像サイズ (偶数)。raw からは分からないため必須。
- `--field-order`: `tff` (上フィールドが先) または `bff` (下フィールドが先)。ffprobe の `field_order` (`tt` が tff、`bb` が bff) で確認できる。必須。
- `--coring`: 縞量で無視する小さな差分の大きさ (0〜255、既定 4)。既定値は暫定の値で、根拠となる資料はない [仮説]。
- 標準入力からフレームを最後まで読み、標準出力へ CSV を書く。処理したフレーム数は標準エラー出力へ出す。
- 1920x1080 の NV12 は 1 フレームが約 3.1MB で、1 話分 (約 24 分) は約 130GB になる。ファイルへ書き出さずパイプで渡し、`-ss` と `-t` で区間を切り出す。
- `-fps_mode passthrough` は、ffmpeg がフレームを複製・削除しないようにするために付ける。
- [未確認] 放送の TS にリピートフィールドフラグが含まれる場合に、ffmpeg のデコードで得られるフレーム数と、MPC-HC (LAV Video) が DMO に渡すフレーム数が一致するかは確認していない。

### 出力する列

先頭行がヘッダー。1 フレーム 1 行で、値がないものは空欄にする。先頭フレームでは前フレームが必要な列が、最終フレームでは次フレームが必要な列が空欄になる。

| 列 | 内容 | 空欄になる条件 |
| --- | --- | --- |
| `frame` | 0 始まりのフレーム番号 | なし |
| `comb_c_mean`、`comb_c_max` | 候補 c の縞量 (全体の平均、最大ブロック) | なし |
| `comb_p_mean`、`comb_p_max` | 候補 p の縞量 | 先頭フレーム |
| `comb_n_mean`、`comb_n_max` | 候補 n の縞量 | 最終フレーム |
| `sad_fs` | 現フレームの先フィールドと前フレームの先フィールドの SAD | 先頭フレーム |
| `sad_ss` | 現フレームの後フィールドと前フレームの後フィールドの SAD | 先頭フレーム |
| `sad_po` | 現フレームの先フィールドと前フレームの後フィールドの SAD | 先頭フレーム |
| `sad_co` | 現フレームの先フィールドと後フィールドの SAD | なし |
| `sad_frame` | 現フレームと前フレームの輝度全体の SAD | 先頭フレーム |
| `mean_luma` | 現フレームの輝度の平均 | なし |

先フィールドは、`tff` なら上フィールド (偶数行)、`bff` なら下フィールド (奇数行)。後フィールドはその反対。SAD はすべて、比較した画素 1 つあたりの絶対差の平均で、輝度のみを対象にする。

### 縞量の定義

- 候補は、現フレームの先フィールドを基準に、組み合わせる後フィールドの取り方で 3 通りある。c は現フレームの後フィールド、p は前フレームの後フィールド、n は次フレームの後フィールド。
- 候補ごとに 2 つのフィールドを行ごとに交互に並べた画像 (weave した画像) を作り、縦に連続する 4 画素ごとに符号反転数を数える。
  - 隣り合う画素の差を 3 つ求め、絶対値が `--coring` 以下の差は 0 とみなす。
  - 隣り合う 2 つの差の符号が逆なら 1 回の反転とする。0 の差は反転に数えない。
  - 1 つの窓の反転数は 0〜2 で、縞のある画素は 2 になりやすい。
- `comb_*_mean` は、全窓の反転数の合計を画素数 (幅×高さ) で割った値で、通常 0〜2 に収まる。
- `comb_*_max` は、フレームを 16 画素×32 行 (フィールドの 16 行) のブロックに分け、ブロックごとの反転数の合計を 512 (16×32) で割った値の最大。ブロックの位置は窓の開始行で決める。端のブロックは、画素数が足りなくても 512 で割る。
- [仮説] この指標は VapourSynth 版の `combMode=0` (符号反転 PCC) と同系統だが、閾値や正規化が同じかは確認していない。c / p / n の組み方は TFM と同じと理解しているが、実動画で確認する [未確認]。
- 黒帯などの除外はしない。画像全体を対象にする。

### 既知の制約

- 輝度のみで、色差は見ない。
- 前後 1 フレームだけを見る。窓付きの系列推定に必要な、より長い範囲の特徴量は出力しない。
- 解析結果の P / I / D との突き合わせは、出力した CSV を元に別途行う。
